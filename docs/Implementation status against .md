## Current release decision

**Not release-ready for general production use.** The stable core can load, modify, validate, and export supported causal Transformer models, with run plans, opt-in Accelerate placement, sharded exports, a bounded language-modeling regression gate, and run audit artifacts. Remaining blockers include the 84 unavailable stages, incomplete model-inspection and safety/capability acceptance, backend-specific quantization coverage, and absent hardware evidence beyond the ARM64 CPU host. The 1.5B ARM64 comparison confirms that smaller int8/int4 checkpoints did not translate to faster CPU generation in that sample and int4 had a substantial PPL penalty; do not treat quantization as an automatic performance win.

## Next controlled increments

1. Expand the new evaluation gate with additional separately versioned capability batteries and corroborate its thresholds across representative models and hardware; keep reasoning/safety claims out of scope until validated datasets and methods exist.
2. Expand the test matrix only where actual architecture/backend support is implemented; add MoE/hybrid adapters behind explicit compatibility checks rather than broad family-name claims.
3. Run paired representative model comparisons on x86-64 CPU, CUDA and each available accelerator, retaining versions, model revisions, dataset samples, thread count, latency/throughput, finite-metric status, and artifact checksums.
4. Promote prototype toggles only after each has a bounded purpose, pipeline contract, safety checks, and positive/negative tests; avoid placeholder modules.
5. Specify plugin, cancellation, timeout, resumability, and rollback contracts before implementing them.
